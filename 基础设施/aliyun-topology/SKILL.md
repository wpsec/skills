# 阿里云资源拓扑更新

## 输入与输出

- 输入：环境名称、目标拓扑文件，以及用户提供的现有拓扑、资源清单、控制台截图/文本、网络配置或关系说明。CSV 是可选资料，不是必需输入。
- 默认目标：用户指定文件；未指定时优先使用当前项目中对应环境目录的 `拓扑图.md`。
- 输出：更新后的 PlantUML 拓扑、简要资产与待确认事项；用户需要时再生成逐项说明资产用途的 Markdown 架构报告。
- 仅处理用户提供的文件和资料，不访问阿里云 API 或其他外部服务，不索取凭据。

## 资料优先级与事实状态

- 开始前确认用户认定的现状依据，以及 CSV/截图等资料是否过期。用户明确说某资料过时或指定拓扑为准时，遵照该口径；过期资料不能推翻现行数量、归属和配置。
- 如果用户没有指定依据，使用最新且直接反映配置的资料作为事实依据；现有目标拓扑作为已接受现状的基线，参考拓扑只用于样式。不同来源冲突时列出冲突并向用户确认，不自行选择一方。
- 内部整理每项结论为“已确认”“有依据的归纳”或“待确认”。资源标签、命名相似、同 VPC 或同集群可帮助找候选资产，但不能单独证明业务调用或流量方向。
- 只把有配置或用户证据支持的链路画成确定关系。待确认关系可用虚线和简短标注；若影响阅读，将其放入图下的待确认说明，不要让猜测看起来像实际链路。

## 工作流程

1. 确认环境、目标文件、资料时效和用户指定的事实依据。检查现有目标图；其他环境的图只用于参考视觉风格，不把其资产或链路当作目标环境事实。
2. 若有 CSV，先查看导出时间和用户对其时效的说明。需要盘点候选资产时运行分析脚本；若 CSV 已过时或用户指定以其他资料为准，不用它覆盖当前资产结论：
   ```bash
   python3 <skill-dir>/scripts/analyze_resources.py <resources.csv> --environment DEV --resource-group "dev资源组"
   ```
   脚本只输出统计和候选摘要，不输出资源 ID、IP 地址或标签值。
3. 建立资产候选清单，按环境标记、用户确认、VPC/ACK 关系和实际配置核对归属。资源组外资产可纳入，但要有环境证据；仅名称相似的项目先列为候选。
4. 与用户逐项收敛不确定项。每轮只询问当前最影响拓扑正确性的少量问题；优先问能确认入口、转发目标、路由、共享依赖或归属的问题。不要为了总览图索取与表达无关的完整监听、全部 DNS 记录、每个 Ingress、Pod、PVC 或挂载点配置。
5. 按入口与负载、集群与计算、管控、后端服务、存储、可观测和出向网络组织资产。重复资源按有意义的类型和数量聚合；用户明确要求逐台列出的资源，提供名称、地址等所需字段。不要把普通账号、快照、证书或日志库逐项塞入图，除非用户要求或它们解释关键关系。
6. 按实际协议和配置表达网络层次，不只凭产品名称分类：TCP/UDP 监听体现四层转发；HTTP/HTTPS 规则按实际配置体现七层转发。Ingress Controller 在使用 Host/路径等 HTTP 规则时承担七层路由；Kubernetes Service 通常提供集群内 TCP/UDP 服务发现和四层转发。对于 CLB → NodePort → Ingress → Service → Pod，分别标注可确认的端口和层次，不把 Ingress 简化成四层负载。
7. 只在有证据时纳入 WAF、云防火墙、ACL、安全组、VPN、NAT、DNS、数据库、备份、监控等配置。资源清单没有某组件不能证明它不存在；用户明确不希望在图中解释的内容不要擅自加上。
8. 按用户指定的阅读顺序和参考图风格组织布局。若本轮对话附有参考图，优先按图面调整；否则沿用目标图样式，前提是用户没有指定其他样式。没有可用参考图或现有样式时，直接使用下方内置默认风格，不依赖本机保存的历史图文件。用户指定标题优先，否则沿用同目录命名习惯；更新日期使用当前会话日期。
9. 尽可能用本机可用的开源 PlantUML 渲染工具渲染并检查实际图面，确认标题、区域顺序、文字可读、连线方向和图面拥挤情况；按需调整源码并重新渲染。若本机没有可用渲染器，说明这一限制，不要把源码能解析等同于图面已验收，也不要直接要求用户截图来替代本地可行的渲染检查。
10. 用户需要架构报告时，按拓扑区块逐项解释已纳入资产的功能、数量和关键配置；共享或混合使用的资源要注明范围，历史任务与当前运行链路分开。未知用途和未确认映射明确标注，不以旧 CSV 填空。
11. 收尾时给出产物路径、主要纳入/排除范围、渲染检查结果和仍待确认事项。Skill、示例和通用说明不得含有当前用户的真实资产名称、资源 ID、IP、账户标识或标签。

## CSV 支持

分析脚本支持常见中英文资源 ID、名称、地域、可用区、资源类型、资源组和标签列名；缺少资源类型列或 CSV 无法解析时，说明具体问题并停止筛选。脚本使用 Python 标准库，不访问网络、不读取环境变量。分析结果仅用于候选盘点，不能替代用户指定的现行资料或配置证据。

## 内置默认视觉风格

这套规则将 DEV 图的视觉样式固化在 Skill 中，因此即使用户没有附图或本机没有历史拓扑文件，也能生成同一风格。只复用视觉表达，不复制 DEV 的环境名称、资产、数量、地址或链路：

- 标题区分三行表达拓扑标题、环境名称和更新日期。
- 使用 `left to right direction`。互联网放在最左侧，主要业务路径向右延伸到工作负载和后端服务；管控、运维、ECS 和出向网络按从上到下的次级区域排列，避免所有主区块挤成一条长横排。按环境实际结构决定区域数量。
- 以浅灰分组框表示逻辑区域：背景 `#F5F5F5`、边框 `#666666`。关闭手绘和阴影；基础间距可用 `nodesep 12`、`ranksep 20`。
- 用简短节点标签和轻量语义色区分资源：普通节点浅蓝 `#E3F2FD` / 蓝边 `#1E88E5`，负载节点浅橙 `#FFE0B2`，说明/待核对信息浅黄 `#FFFDE7`；需要表达公网或运维资源时可用浅绿、浅青。颜色含义保持稳定，增加的颜色要在图例说明。
- 优先使用 PlantUML 的 `rectangle` 分组和合适的 `node`、`database`、`storage` 等节点形状。连线可弯曲；隐藏约束只调整排布，不代表真实关系。
- 默认图例区分业务/网络转发、DNS 查询、VPN 通道和待确认关系。DNS 线明确标成“仅解析，不承载应用流量”；任何虚线或颜色都必须有清楚含义。
- 只在图上保留总览需要的资产名称、数量、关键地址和协议/端口；避免把监听清单、所有域名、Pod/PVC 配置或操作说明塞进节点。用户明确要求展示的内容优先。
